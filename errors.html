20 proxy client error strings — client, failure stage, first fix

Each entry states where the failure happens, not just what it says. Most of these fail before traffic ever reaches a node, which is why "reinstall it" and "change your node" are the two most common wrong answers.

Read this before you change anything

Save the first error line, verbatim. The first error is the cause; the lines after it are usually cascade. Copy it including the code and any quoted path.

Change one variable per round. Reinstalling, deleting the profile and switching nodes in the same session destroys the evidence you need.

Redact before you post. Subscription URLs, tokens, node passwords and unmasked logs are credentials. Redact them before pasting into an issue.

What each stage means

StageWhat it rules out
DNS rewriteNot the subscription, not the node. The client failed while changing the system DNS setting.
Profile fetch / parseThe download or the YAML/JSON parse failed. Node health is irrelevant.
Service installThe helper service is missing or blocked. Nothing downstream can work until it is installed.
Core IPC handshakeThe GUI started but the core did not report ready. Usually a leftover process or a locked port.
Traffic takeoverSystem proxy or TUN is not actually capturing traffic. Compare with the client fully off.
Rule file loadA data file is missing or from a mismatched version.
Subscription parseThe payload is not in the format the client expects — often base64 when YAML was assumed.
Core startThe core binary failed or its listen port is taken.
Config schemaThe config contains a field this version rejects — check the version before editing values.
TUN helper / privilegeThe OS refused the privileged operation. Not a config problem.
